# 화면 언어 (한국어 · English)

콘솔의 **⚙️ 설정 팝오버 → 화면 언어 · Language** 에서 `🇰🇷 한국어` / `🇺🇸 English` 를 고릅니다. 고른 언어는 앱 데이터 폴더의
`settings.json` 에 남고(`{"language": "en"}`), 주제어실 콘솔과 현장 단말 두 창이 함께 바뀝니다 (`language_changed` 이벤트).
시작할 때 언어를 정하려면 `BLUEPRINT_LANG=en` 을 줍니다 (설정 파일보다 앞섬).

## 무엇이 바뀌고 무엇이 그대로인가

| 범위 | 영어 화면에서 | 어디서 |
| --- | --- | --- |
| 프런트 글 (단추 · 제목 · 안내 · 오류) | 영어 | 컴포넌트마다 `t("한국어", "English")` (`app/src/i18n/index.tsx` 의 `useT`), 모듈 함수는 `tr()` |
| 백엔드가 보낸 글 (원장 이름 · 판정 이름 · 단계 · 감사 기록 · 결재 · 가드레일 · 검색 "왜" · 판단 질문 · 사실) | 영어 | `app/src/ipc.ts` 가 `invoke` · `listen` 응답을 화면에 넘기기 전에 `translate.ts` 로 바꿈 |
| 마스터 도면 그림 (P&ID · MEP · SLD · NET 10장) | 영어 그림 | `drawing_image` 가 `core/fixtures/drawings/en/*.png` 를 줌 (같은 배치 · 같은 좌표) |
| Zoro-1 이 쓰는 조치 절차서 원인 요약 (AOP · EOP) | 영어로 씀 | `core/src/i18n.rs` 의 영어 지시문 · 요청문, `drafting::draft_aop_in` — 숫자 · 코드 대조(factcheck)는 같음 |
| 자연어 질의 | 영어로 침 | 엔진(`core/src/search`)이 영어를 그대로 읽음: 영어 낱말 목록 · Stanza 원형 · en.json 의 원장 영어 이름 · 다국어 임베딩 (결과는 다시 영어로). 예전에는 화면의 `i18n/query.ts` 가 한국어 낱말로 옮겨 보냈습니다 ([search.md](search.md)) |
| 엔진 · 원장 · 판정 규칙 · 모델 입력 | 한국어 그대로 | 판정과 모델은 언어와 상관없이 같은 값을 냅니다 |
| 현장 서류 (계기 점검표 · Red-line 스캔)와 그 판독 글 | 한국어 그대로 | 현장 서류는 현장의 언어입니다. gocr 가 읽은 원문(예: 작업자 서명)은 바꾸지 않습니다 |
| 판독 · 델타 색인 | 한국어 마스터 | 현장 스캔이 한국어 서류라 델타는 언제나 한국어 마스터와 견줍니다 |

## 번역 표 (`app/src/i18n/en.json`)

`translate.ts` 는 글 한 줄을 이 차례로 바꿉니다 (여러 줄은 줄마다, 한 번 바꾼 글은 기억).

1. `exact` — 글 전체가 같으면 그 영어 (판정 이름 · 단계 · 메시지 · 원장의 긴 문장)
2. `spans` — 원장 이름 전부와 긴 통째 글을 글 속 어디서든 먼저 바꿈. 숫자 틀이 이름 속 `103동` 같은 조각을 먼저 바꿔 이름이 깨지는 것을 막습니다
3. `patterns` — 정규식 `[찾기, 바꾸기]` 를 차례로 모두 적용 (엔진 문장 틀 → 동 · 층 · 초 · 홉 같은 숫자 단위)
4. `exact` 다시 — 틀을 거친 글이 통째로 표에 있으면
5. `names` + `phrases` — 남은 낱말 (긴 것부터)

바꾼 뒤에도 한글이 남으면 `window.__i18nMisses()` 에 모입니다. 감사 모드(`window.__i18nAudit = true`)에서는 백엔드가 보낸 한글 글을
언어와 상관없이 `window.__i18nSeen()` 에 모읍니다.

표는 손으로 고치지 않고 `scripts/i18n/` 에서 만듭니다.

```bash
# 원장 · 시나리오 글은 en_fixtures.py, 엔진이 만드는 글은 en_engine.py 에 적고
python scripts/i18n/build_en.py --write                     # en.json 쓰기
python scripts/i18n/build_en.py out/shots_ko/i18n_seen.json # 쓰지 않고, 모은 글 중 영어로 안 바뀌는 것만 i18n_misses.txt 로
```

빠진 글 찾기: 한국어 화면으로 `node scripts/e2e/console.js --audit` (또는 `record.js --audit`)를 돌리면 `i18n_seen.json` 이 나옵니다.
영어 화면 E2E(`--lang en`)는 스크린샷마다 화면에 남은 한글 줄과 `__i18nMisses()` 를 `i18n_visible.json` 에 남깁니다.
앱이 `tauri dev` 로 돌고 있으면 `en.json` 을 쓰는 순간 vite 가 화면을 다시 읽으니 E2E · 촬영 중에는 쓰지 않습니다.

용어는 `app/src/i18n/GLOSSARY.md` 를 따릅니다 (Control Console, Shift Supervisor, Co-sign, Interlock, Archived Record …).
합성 인물 이름은 로마자(예: 김태현 → Kim Tae-hyun, 가린 이름 김○현 → Kim ○-hyun)로 씁니다.

## 영어 도면

```bash
python scripts/gen_pid_drawings.py --lang en                 # 발전소 P&ID 5장
python scripts/gen_pid_drawings.py --lang en --domain aidc   # 데이터센터 MEP · SLD · NET 5장
```

같은 시드 · 같은 배치로 그리고 글만 `en.json` 으로 바꿉니다 (생성기 고유 글 — 표제란 머리 · 일람표 머리 · 서명란 · 범례 — 은 생성기 안의 `L()` · `DOMAINS[…]["en"]`).
한국어 마스터 · 현장 스캔 · A0 는 이 옵션과 상관없이 바이트까지 같습니다 (`--lang` 없이 다시 만들어 해시로 확인).
