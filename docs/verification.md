# 검증 결과

모든 수치는 **합성 데이터**(합성 원장 · 합성 시계열 · 합성 도면과 스캔)에서 잰 값입니다. 실제 발전소 계측이나 실제 스캔이 아니므로 제품 성능으로 말하지 않습니다. 방향을 보는 용도입니다.

## 1. 시험 (모델 없음)

```bat
cargo test -p blueprint-core --no-default-features     :: 단위 292 + 시나리오 E2E 13
cargo test -p blueprint-models                          :: 20 (가져오기 · 하드 링크 · 다운로드)
```

| 묶음 | 수 | 무엇을 |
| --- | --- | --- |
| 코어 단위 (발전소 도메인) | 292 중 약 110 | KKS 자리별 교정 · 편집 거리 · 모호하면 고르지 않음, 홉 뎁스 · 순환, 변곡점 · 교차 · 기울기 · TTF · 동결 · 잡음, 인과 시차 · 역류 여파, SDS 트리거 · 봉인 변조 검출, 보팅 · 시점 동기화, MOC 대조 · 권한 · 설계 한계 · 구버전 도면, 판정 축 · 기준, AOP 초안 재시도 · 템플릿, 현장 단말 소명 · 누출 차단, 마이닝 · Mermaid |
| 코어 단위 (zoro-gravity 엔진) | 나머지 | 가져온 엔진의 기존 시험 (GPU · 실제 모델 시험 10개는 `--ignored`) |
| 시나리오 E2E | 13 | P1 ~ P7, 서명 재요청, 초안 숫자 환각 → 템플릿, 모델에 근무자 정보가 가지 않음, 실명 열람 감사 |

판단 · 글쓰기 자리에는 정해 둔 답을 내는 대역을 꽂아, 규칙 · 가드레일 · 결재 흐름을 모델과 떼어 시험합니다.

## 2. 실제 모델 (ROCm, AMD Radeon RX 6600 8 GB)

`run\windows\rocm.bat plant_probe out\field out\plant_probe.json` (zoro-gravity 에서 가져온 q8 모델, 가중치 상주 관리 그대로). 결과 전문은 `out/plant_probe.json`, 모델 기록은 `BLUEPRINT_TRACE` 파일입니다. 아래 표는 **두 번째 실행**(2026-11-04 03:00 KST, 2.4절의 수정 뒤) 값이고, 첫 실행과 달라진 점은 2.4절에 적었습니다.

- **AOP 초안 6/6 이 모델 글이고 첫 시도에 숫자 · 설비 코드 대조를 통과**했습니다 (두 실행 모두, 템플릿으로 내려간 것 없음). 예 (P1): "102동 3F (EL.+18.0m) 고압터빈(10MAA10ST001) 주증기 압력 계측에서 채널 A 단독으로 14.2 MPa로 편차하고 있으며, 현장 게이지와 나머지 채널(B, C)은 정상적인 26.0 MPa 값을 표시합니다. 이는 전송기 단독 편차로 판단되며, AOP-102-IC01 … 절차에 따라 조치해야 합니다."

## 3. 앱 E2E (실제 앱 두 창 · ROCm · 실제 모델)

`tauri dev --release --features rocm` 로 띄운 앱(주제어실 콘솔 · 현장 단말 두 창)에 WebView2 원격 디버깅(9222)으로 붙어 `node scripts/e2e/console.js --shots out/shots` 가 실제로 누릅니다. 현장 스캔은 스캐너 폴더(`BLUEPRINT_SCANNER_DIR`)에 합성 스캔을 넣고 단말의 [도면/계기 스캔] 을 눌러 SigLIP2 · gocr 로 읽습니다. 현장 단말은 화면마다 금지어(판정 코드 · 확신도 · 단계 이름 · `jev_head` · 마인드맵 · 근본 원인 · 고위험 · 보팅 · DCS 표시값)를 검사합니다. 화면 사진은 `out/shots/` (저장소 밖) 입니다.

처음 돌렸을 때 찾아 고친 것:

- 소명 화면 안내문의 "Zoro-1" 이 금지어에 걸렸습니다. 기획안 화면 문구("자유 서술 → Zoro-1이 표준 코드로 자동 분류")이므로 금지어를 모델 이름 대신 "모델이 무엇을 판단했는지"(단계 이름 · 확신도 · 판정 코드)로 좁혔습니다 (`privacy::FIELD_FORBIDDEN`).
