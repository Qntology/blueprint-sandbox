## 1. 4.2 구현: 판독 대안을 근거로 한 두 글자 교정

### 1-1. 흐름

1. **디코더** (`ai/attention.rs` `top3`, `ai/speculative.rs` `Pick`): 확정하는 토큰마다 1위와 함께 2 · 3위 토큰과 확률을 남깁니다. 자기 추측 · 블록 초안의 검증 스텝도 같은 로짓에서 뽑으므로 디코딩 결과 · 속도는 그대로입니다.
2. **gocr** (`ai/gocr/mod.rs` `alt_pieces`): 1위 확률이 `SHADOW_CEIL` 0.92 밑인 스텝만, 확률 `MIN_ALT_PROB` 0.08 이상인 대안 토큰을 **바이트 조각**으로 남깁니다 (`AltPiece { at, conf, alts }`, `OcrOutput::alt_pieces`).
   토큰 바이트를 이어 붙인 것이 판독 글과 다르면(정리 · 특수 토큰) 자리를 믿을 수 없어 비웁니다.
3. **추출** (`extract.rs`): 조각마다 `PageCrop::alts` 로 넘기고, Red-line 서명자 이름이 원장에 없으면
   ① 날짜 줄의 한 글자 차이(`person_one_off`, 예전 그대로) → ② 날짜 줄 · 표 칸의 3 ~ 4글자 한글 이름이 원장 이름과 두 글자 이내로 다르고, **다른 글자마다** 글자 확신 < 0.95 이면서
   `gocr::alt_supports` 가 참일 때만 (`Lattice::person_with_evidence`) 고칩니다. 교정 기록의 칸은 `서명자 이름 (판독 대안 근거)` 입니다.
4. `alt_supports(text, pieces, i, want)`: i 번째 글자를 `want` 로 바꾼 글을 만들고, 그 글자 바이트에 닿는 조각(글자 안에서 시작하거나 바로 앞 공백 `Ġ` 부터)의 대안 바이트가
   바꾼 글의 같은 자리에서 이어지면 근거입니다. 글자 중간에서 시작한 조각은 앞 바이트가 두 글자에서 같아야 하고, 원래 글과도 이어지는 조각은 대안이 아니라 셈하지 않습니다.

### 1-2. 글자가 아니라 바이트인 까닭 (처음 구현이 틀렸던 곳)

gocr 토크나이저는 바이트 수준 BPE 이고 한글 토큰이 232개뿐이라, 같은 자리의 다른 글자는 토큰 수부터 다릅니다.

| 글 | 토큰 |
| --- | --- |
| ` 입래현` (B4 판독) | `Ġìŀ` (20 EC 9E) · `ħ` (85) · `ëŀĺ` (EB 9E 98) · `íĺ` (ED 98) · `Ħ` (84) |
| ` 김태현` (원장) | `Ġê` (20 EA) · `¹` (B9) · `Ģ` (80) · `íĥ` (ED 83) · `ľ` (9C) · `íĺ` · `Ħ` |

처음에는 2 · 3위 토큰 하나를 그 자리에 넣고 다시 풀어 바뀐 **글자**를 대안으로 삼았습니다. 그러면 `Ġìŀ` 자리에 `Ġê` 를 넣어도 뒤의 `ħ` 와 이어져 깨진 글자가 되고,
한글 이름에서는 근거가 한 번도 나오지 않습니다 (A0 B4 실측: 교정 0건). 바이트 조각으로 바꾸면 '입' 자리 첫 스텝의 2위 `Ġê` 는 " 김"(20 EA B9 80)의 앞과 이어지고,
'래' 자리의 2위 `íĥ` 는 '태'(ED 83 9C)의 앞과 이어집니다. 첫 바이트만 같은 다른 글자(EA 로 시작하는 가 ~ 깋)도 같은 근거를 받지만, 고칠 이름은 원장 후보로 묶여 있습니다.

### 1-3. 실측

- 시험 (CPU, 모델 없음): `gocr::tests` 3개(바이트 근거 · 대안이 아닌 조각 · 디코더 대안 → 조각 자리), `extract::tests::a_two_letter_signer_misread_is_fixed_only_with_decoder_evidence`
  (줄 · 표 칸 두 꼴에서 두 자리 근거 → 김태현 E102, 한 자리만 · 확률 0.05 · 확신 0.97 이면 그대로), `tokenizer::tests::token_bytes_give_the_raw_bytes_of_split_hangul`.
- 실제 모델 (ROCm, RX 6600, `delta_probe`, 조각마다 확신 0.95 밑 글자와 대안 조각을 JSON 에 남김):
  - **A0 B4 델타 판독 `2026-11-04 입래현`**: 글자 확신 입 0.519 · 래 0.821. '입' 앞 공백 스텝(확신 0.545)의 2 · 3위가 `20 EA`(0.20) · `20 EC A7`(0.10) 이라
    **입 → 김 은 근거가 있습니다**. 그런데 '래' 스텝(확신 0.821)의 2위는 `EB A0 A5` = '력'(0.15) 이고 '태'(ED 83 9C)는 상위 3 안에 없어, 두 글자 교정은 **하지 않았습니다**
    (작업자 비움 그대로). 모델이 보지 않은 글자를 원장 이름만 보고 채우지 않는다는 철창 3 이 실제 판독에서 그대로 작동한 것입니다.
    같은 타일을 전부 읽으면 표 칸에서 `김태현` 을 바로 읽어 E102 입니다 (델타의 좁힌 조각에서만 오독).
  - P3 · P3F · P1 의 값(MOC · 수치 · 작성자 · 도면 · 개정)은 기준 실행(`out/delta_pre_plant.json`)과 같습니다. P3F 델타의 한 글자 교정(`김래현 → 김태현`)도 그대로입니다.
  - 판독 시간은 기준과 같은 범위입니다 (기준 → 지금: P3 전부 36.6 → 36.8 s · 델타 8.6 → 8.9 s, P3F 33.9 → 34.7 · 7.0 → 7.3 s, P1 11.7 → 12.1 s, A0 델타 12.1 → 12.4 s;
    같은 시각 CPU 에서 logis-center 빌드가 돌았음). 상위 3 은 1위를 고르던 로짓에서 같이 뽑습니다.

## 2. 하지 않은 것 · 다음

- 1.2: 비전 타워 Q8 · Q6_K 를 모델 설정 도구의 정밀도 기준으로 재 보기 (출력 상대 오차). 언어 모델은 BF16 원본이 생기기 전에는 못 함.
- 3.1: 패치 수준 실측 — 합성 도면 조각의 merger 출력과 그 조각 글의 토큰 행(입력 공간이라 회전 없이도 비교 가능) 코사인으로, 글자 있는 패치 · 없는 패치 AUC 를 SigLIP2 와 나란히.
- 4.2 를 사번 · KKS 로 넓히는 것은 하지 않았습니다. 지금 편집 거리 교정은 근거 없이도 유일하면 고치므로, 근거를 요구하면 교정이 줄어듭니다 (근거는 두 글자 이상 다를 때만 씀).
