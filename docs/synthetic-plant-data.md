# 합성 발전소 데이터 정의

발전소 DCS · CMMS(정비 이력) · 변경관리 시스템과 연계가 없어서, 원장과 계측을 **합성 데이터로 미리 넣어 둔 상태**로 진단합니다 (zoro-gravity 의 합성 관계망 · 대장과 같은 원칙). 값은 모두 합성이고 실제 발전소 · 설비 · 사람이 아닙니다. 실제 연계가 생기면 `core/src/lattice.rs` 의 조회 함수와 `core/src/scenario.rs` 의 계측 공급 자리가 바뀝니다.

| 파일 | 만드는 곳 | 내용 |
| --- | --- | --- |
| `core/fixtures/synthetic_db.json` | 손으로 작성 (시드 원장) | 호기 · 섹터 · 층 · 도면 · 설비(KKS) · 센서 기준치 · 계통 간선 · 도면 간 연결점 · DCS 보팅 · MOC 원장 · 근무자 권한 · AOP 절차서 · A0 종합 도면 배치 · 선행 절차 인터록 · 도면 기호 범례 · 정비 이력 |
| `core/fixtures/plant_scenarios.json` | `python scripts/gen_plant_cases.py` | 시나리오 8개, 센서 22개 × 1초 표본 151개 (t = -60 ~ +90 초) |
| `core/fixtures/drawings/PID-*.png · .json` | `python scripts/gen_pid_drawings.py` | 마스터 P&ID 5장 (2000 × 1400) 과 정답 영역 |
| `out/field/*.png · .json` | `python scripts/gen_pid_drawings.py` | 현장 스캔: 계기 점검표(P1), Red-line(P3 · P3F) 과 정답 값. 저장소에 넣지 않습니다 |
| `out/symbols/` | `python scripts/gen_pid_drawings.py --symbols` | 설비 심볼 그림 사전 표본(학습 520 · 시험 260, 시드가 다름)과 명판 훼손 도면 L1 ~ L3 (5장씩). 저장소에 넣지 않습니다 |

## 1. 시드 원장 (`synthetic_db.json`)

### 1.1 공간 뎁스 (Lv1 ~ Lv5)

| 뎁스 | 원장 항목 | 값 |
| --- | --- | --- |
| Lv1 호기 | `plant.units` | `10` 1호기 1.2GW, `20` 2호기 1.2GW, `00` 공용설비. 설비는 모두 1호기(`10…`) |
| Lv2 섹터 | `sectors` | 101동 보일러동 `10UHA`, 102동 터빈건물 `10UMA`, 103동 급수·보조펌프동 `10ULB`, 104동 전기·제어동 `10UBA`, 105동 환경·통풍설비동 `10UQA` |
| Lv3 층 | `floors` | B1F(EL.-6.0m) · 1F(EL.+0.0m) · 2F(EL.+9.0m) · 3F(EL.+18.0m 운전층) · 4F(EL.+27.0m) · 5F(EL.+65.0m 보일러 상부) · 옥외 |
| Lv4 도면 | `drawings` | PID-101-HAD Rev.5 · PID-102-MAA Rev.4 · PID-103-LAB Rev.3 · PID-104-BBA Rev.2 · PID-105-HLB Rev.2 |
| Lv5 설비 | `equipment` | KKS 12글자 34개. 도면 안 정규화 좌표(`bbox`)가 사전 인덱싱 결과입니다 |

KKS 는 `10`(호기) `LAB`(계통) `10`(계통 번호) `AP`(설비 종류) `001`(번호) 꼴입니다. 센서 태그는 설비 종류 자리에 측정 코드(`CP` 압력 · `CT` 온도 · `CY` 진동 · `CF` 유량 · `CG` 개도 · `CE` 전기량 · `CL` 수위 · `CQ` 농도)가 들어갑니다.

### 1.2 계통 간선 (마인드맵)

간선 39개는 원인에서 결과로 향합니다 (흐름 방향, 통풍은 흡인 방향). 간선마다 매체(전력 · 복수 · 급수 · 증기 · 회전축 · 윤활유 · 해수 · 연료 · 공기 · 연소가스 · 통풍)와 **물리적 전파 지연 범위 `lag` [최소, 최대] 초**가 있습니다. 인과 시차 판정은 경로의 지연을 더한 범위를 씁니다.

- 기획안 P2 의 경로: 103동 주급수 유량조절밸브 `10LAB20AA102` → (도면 점프 `OPC-103-101`) → 101동 수냉벽 · 노 `10HAD10BB001` → 최종과열기 `10HAH10BB001`. 지연 [1.5, 8.0] + [0.5, 4.0] = **[2.0, 12.0] 초** (기획안의 고압급수 배관 Δt 범위)
- 흐름 센서가 있는 간선(`flow_tag`)은 프로세스 마이닝의 간선 굵기(`현재 / 정상`)가 됩니다.
- 순환이 있습니다 (복수 → 급수 → 증기 → 복수, 발전기 → 변압기 → 차단기 → 펌프). 탐색은 홉 한도와 방문 표시로 끊습니다.

도면을 넘는 간선 13개는 모두 연결점(`connectors`)이 있고, 출발 도면의 오른쪽 · 도착 도면의 왼쪽 상자 좌표를 가집니다 (원장 로딩 시 검사). 급수 바이패스 → 수냉벽(`OPC-103-101B`)은 주 조절밸브의 점프 상자를 함께 씁니다.

개선안(Part 8-4)으로 더한 것:

- **급수 바이패스 밸브** `10LAB20AA103` (103동 2F, PID-103-LAB 오른쪽 위 칸) 과 개도 센서 `10LAB20CG103` (정상 0 %), 간선 주급수펌프 → 바이패스(`바이패스`) · 바이패스 → 수냉벽(`고압급수`, 지연 1.5 ~ 8초). 시나리오 생성기는 이 센서를 따로 시드를 잡은 난수로 뽑아 기존 시나리오 값이 하나도 바뀌지 않았습니다 (`LATE_TAGS`).
- **선행 절차 인터록** `interlocks`: AOP-103-FW02 (대상 `10LAB20AA102`, 고장 `VALVE_STUCK_LOW`) 3단계 — ① Depth -1 주급수펌프 A 토출압 ≤ 30.0 MPa ② Depth 0 바이패스 개도 ≥ 50 % ③ 현장 LOTO 서명. 단계의 깊이는 원장을 읽을 때 계통 그래프로 검사합니다.
- **도면 기호 범례** `symbol_legend`: 심볼 10종(펌프 · 밸브 · 터빈 · 팬 · 열교환기 · 용기 · 차단기 · 변압기 · 발전기 · 제어반)과 그 심볼로 그리는 설비 종류. 생성기와 코어(`Lattice::symbol_for_kind`)가 같은 표를 씁니다. 미분탄기 · 버너 · 베어링은 심볼이 없습니다.
- **A0 종합 도면 배치** `a0_drawings`: `PID-100-ALL-A0` (A0 1189 × 841 mm, 150 DPI 7,016 × 4,961 px, 4 × 4 타일 · 겹침 10 %), 마스터 5장의 왼쪽 위 좌표. 그림은 `gen_pid_drawings.py` 가 `out/a0/` 에 만듭니다 (354 KB, 저장소 밖). `--a0-dpi 300` 이면 같은 배치를 2 배 해상도로 다시 그린 300 DPI 판(14,032 × 9,922 px, `PID-100-ALL-A0@300dpi.png`)을 만듭니다.

## 2. 시나리오 (`plant_scenarios.json`)

시계열은 기준 시각 `t0` 에서 -60 ~ +90 초, 1초 간격입니다. 기준 구간은 처음 20초이고, 평상 흔들림은 데드밴드의 12% (σ) 로 넣었습니다. 이상은 (시각, 값) 꼭짓점을 잇는 꺾은선입니다. `now_s` 는 분석 시각입니다.

| ID | 내용 | 기대 판정 |
| --- | --- | --- |
| P1 | 주증기 압력 채널 A 만 26.0 → 14.2 MPa (t = -2 ~ +4 초), B · C 와 현장 게이지(+65 초, 14:21:05) 26.0 | `G2_SENSOR_DRIFT_ISOLATED` (현장 확인 전 HOLD, 트립 보류) |
| P2 | 급수조절밸브 개도 78 → 18% (t = 0), 급수 유량 1,850 → 1,120 t/h, 펌프 토출 28.5 → 29.4 MPa (배압, 약 1.2 초 뒤), 과열기 온도 610 → 638 °C (약 4.3 초 뒤 변곡, 8.3 초 경보) | `G3_ADVERSE_UPSTREAM_CAUSE` · 원인 밸브 2홉 · AOP-103-FW02 |
| P3 | 펌프 토출 29.4 MPa (옛 경보 29.0 초과), Red-line 31.0 MPa · MOC-2026-1104 · E102 서명 · PTW 확인 | `G2_MOC_VERIFIED` · 오버레이 반영 |
| P3F | 같은 Red-line 의 위조 수치 35.0 MPa | `G2_REJECT_CONTRADICTION_LOCK` |
| P4 | 고압터빈 1번 베어링 진동 45 → 212 µm, 윤활유 · 주증기 정상 | `G3_VIOLATION_HIGH_RISK` · AOP-102-TB01 |
| P5 | 과열기 온도 t = 0 한 표본만 810 °C | `G1_SPIKE_FILTERED` → `G3_ELIGIBLE_NORMAL` |
| P6 | 윤활유 온도가 t = -40 부터 56.000 °C 로 고정 (분산 0) | `G1_SENSOR_FLATLINE` · AOP-COM-IC02 |
| P7 | 유인통풍기 전류 360 → 282 A (t = 0), 노내 압력 2초 뒤부터 초당 0.06 kPa 상승, 경보 전 TTF ≤ 30 초 | `HIGH_SLOPE_PRE_ALARM` · 원인 유인통풍기 · AOP-105-DR01 |

수치는 기획안의 서술(4.2초, 638.0 °C, -39.5% 등)에 맞춰 만들었지만, 화면과 보고서에 나오는 시차 · 기울기는 이 시계열에서 **다시 계산한 값**입니다 (예: P2 의 관측 시차는 약 4.3초). 생성기는 시나리오마다 따로 시드를 줘서 하나를 고쳐도 다른 시나리오 값이 바뀌지 않습니다.

## 3. 합성 도면 · 스캔

- 마스터 P&ID: 표제란(도면번호 · 개정 · 건물), 설비 상자(KKS · 이름 · 위치 · 센서 정상치 · 오른쪽 위 60 px 칸의 설비 심볼), 같은 도면 안 배관(매체별 선 모양), 도면 간 점프 상자, 운전 기준치 일람표, 고정 범례(안내문), 기술책임자 서명란. 앱의 도면 뷰가 이 이미지 위에 원장 `bbox` 를 얹습니다.
- 배관은 상자를 가로지르지 않습니다. 설비 상자가 4열 × 3행 격자에 있어서, 선은 열 사이 통로(폭 40 px)와 행 사이 통로(높이 49 ~ 77 px)로만 꺾어 갑니다. 같은 통로를 여러 선이 지나가면 옆 줄로 띄우고, 한 상자의 같은 변에 선이 여럿 붙으면 붙는 자리를 위아래로 벌립니다. 배관 이름은 행 통로의 가로 구간 위(흰 바탕으로 선을 끊고)나 열 통로 안(90도 돌려)에 씁니다.
- 생성기가 그린 심볼을 도면 JSON 의 `symbols` 에 (설비 · 심볼 · 잉크 상자 · 칸) 으로 남깁니다. 그림 사전 · 후보 추출 실측의 정답입니다.
- 생성기가 그린 꺾은선을 도면 JSON 의 `pipes` 에 정규화 좌표로 남깁니다(`via` 는 도면 간 점프 커넥터). 앱의 프로세스 마이닝 흐름 오버레이는 이 좌표를 그대로 따라가므로 이미지의 선과 어긋나지 않습니다.
- Red-line: PID-103-LAB 위에 붉은 펜으로 일람표 경보한계를 긋고 새 값을 적고, 빈 자리에 `MOC-2026-1104 / 10LAB10AP001 토출압력 경보 / 29.0 MPa → 31.0 MPa / 날짜 · 이름` 과 서명 · 직인을 넣습니다.
- 계기 점검표: 점검 일시 · 점검자 · 사번 · 관할 섹터 · 설비 KKS · 센서 태그 · 현장 실측치 · 단위를 손글씨(궁서 글꼴을 글자마다 흔듦)로 적고, 아날로그 게이지 그림과 서명을 넣습니다. 붓 글꼴의 `1` 이 `l` 처럼 보여 KKS 오독 교정(상호작용 ①)이 실제로 일어납니다.
- 스캔 흉내: ±0.8° 기울기 · 흐림 · 종이 색 · 잡음.

실제 스캔이 아니므로 판독 정확도를 제품 성능으로 말하지 않습니다.
